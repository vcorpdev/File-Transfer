Zero-knowledge by design.

Key generated on your device

An encryption key is generated in your browser, then the file, its name and its metadata are encrypted with AES-256 in your browser. Only then are they sent to our server, under a random identifier, also generated on the browser side.

Stored as noise.

So our servers know nothing, never did anyway. They receive an unreadable block of data, which they have to store under an equally unreadable identifier, always with the same .bin extension.

Opened once. Then gone for good.

The URL used to retrieve the file contains the ID of the file to retrieve and the decryption key. The key sits after the # symbol in the URL, so it is never sent in the request. It will decrypt the file in your browser, and the file on the server will be immediately destroyed.

What our server knows.

Here is everything that reaches us, and everything that never does.

It knows

  • A random 256-bit IDDrawn apart from your key. It tells nothing about it.
  • The size of the encrypted file
  • When it was uploadedOnly to delete it after 48 hours.

It never knows

  • The file name
  • What is inside
  • The key
  • Who you areNo account, no cookies.

We can’t read your files. Not even with a court order: we never had the key.
